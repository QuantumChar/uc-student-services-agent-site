1. Overview

This guide helps education teams and student builders create a University of California Student Services Agent that answers student questions with official sources and can optionally use Work IQ for personal M365 context.

Use case: “What are my campus deadlines, service contacts, and forms?” answered from UC student service websites with citations.

2. Architecture

  • Prompt Agent: Foundry-hosted agent with clear student-support instructions.
  • Custom Web Grounding: Bing Grounding + Custom Search scope to specific UC campus domains.
  • Foundry Work IQ: Optional A2A tool for signed-in user context (mail, meetings, docs) when requested.

3. Prerequisites

  • Azure subscription and Azure AI Foundry project
  • Deployed chat model in Foundry project
  • Project access permissions (Foundry User / Project Manager)
  • For Work IQ: BYO Entra app, admin consent, and M365 Copilot licensing

4. Step-by-step build

Step 1: Define scope

Start with 4 core areas: admissions, financial aid, registrar, and campus life. Identify the exact campus domains you will permit (for example, *.berkeley.edu or *.ucla.edu).

Step 2: Create the Prompt Agent

In Foundry, create a prompt agent named uc-student-services-agent using your deployed chat model and baseline instructions that require source-backed answers.

Step 3: Configure custom web grounding

  1. Create Grounding with Bing Search resource.
  2. Create a Foundry project connection to that resource.
  3. Use Bing Custom Search configuration to limit retrieval to campus domains.
  4. Attach the Bing grounding tool connection to the agent.

Note: Foundry Web Search tool is simpler, but domain-restricted campus scoping requires Bing Custom Search.

Step 4: Configure Foundry Work IQ

  1. Create a RemoteA2A project connection to https://workiq.svc.cloud.microsoft/a2a/.
  2. Set OAuth2 with BYO Entra app.
  3. Grant required scopes: api://workiq.svc.cloud.microsoft/WorkIQAgent.Ask and offline_access.
  4. Complete tenant admin consent flow.
  5. Attach Work IQ tool to the agent.

Step 5: Add production-safe instructions

  • Always cite campus source URLs for policy or deadline answers.
  • If sources conflict, show both and recommend official office contact.
  • Never fabricate dates, forms, or office details.
  • Use Work IQ only when users ask for personal context.

Step 6: Validate with student scenarios

  • “What are add/drop deadlines for this term?”
  • “Where do I get FAFSA help on campus?”
  • “Summarize my upcoming advising meetings.” (Work IQ path)

5. Test prompts

  • “Give me registrar office hours and links.”
  • “What documents are needed for undergraduate financial aid appeals?”
  • “Show me international student support contacts and cite sources.”

6. Quality checklist

  • Responses contain valid source links
  • Date and deadline answers are current
  • No hallucinated forms or policy statements
  • Work IQ requests are explicit and privacy-safe

7. Deploy to GitHub Pages

This project includes a GitHub Actions workflow at .github/workflows/deploy-pages.yml. Push to the repository’s default branch, then enable Pages in GitHub using “GitHub Actions” as the source.
